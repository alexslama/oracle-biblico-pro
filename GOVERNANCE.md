# Governance

SHAMIR is currently maintained by **Alex Slama** as an independent open-source project.

## Decision principles

Project decisions prioritize, in order:

1. reproducible and inspectable behavior;
2. honest capability and evaluation claims;
3. source provenance and licensing;
4. local-first usability and privacy;
5. maintainability and testability;
6. compatibility with community contributions.

## Contributions

Small, focused pull requests with tests and clear verification are preferred. Significant architecture changes should begin as an issue so assumptions, interfaces, and evaluation criteria can be discussed publicly.

A contribution may be declined when it:

- introduces unverifiable or misleading capability claims;
- redistributes material without clear rights;
- silently sends user corpus/query data to hosted services;
- weakens source provenance, transparent failure states, or evaluation boundaries;
- adds large dependencies without a demonstrated need;
- cannot be maintained or tested within the project scope.

## Maintainer responsibilities

The maintainer is responsible for reviewing contributions, maintaining releases, documenting limitations, addressing security reports, and avoiding claims of adoption or accuracy that are not supported by public evidence.

## Future maintainers

If sustained external contributors emerge, SHAMIR may add additional maintainers based on consistent technical contributions, constructive review work, and demonstrated alignment with the project's transparency and provenance principles. Any governance change should be documented publicly in this file.
